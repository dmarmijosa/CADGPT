# file-integrity-anti-corruption (NEW)

Purpose: Prevent corruption and downstream viewer/slicer crashes through deep binary STL coordinate and structural validation, native CAD/3D magic header byte verification, and multi-stage pre-delivery gates across upload, storage, and file serving pipelines.

---

### Requirement: Binary STL Deep Structural and Coordinate Validation
All binary STL files handled by the platform (generated by agents, uploaded to the API, or served to clients) MUST undergo deep structural and coordinate validation:
1. **Size Invariant Formula**:
   - The file size MUST be at least 84 bytes (80-byte header + 4-byte facet count).
   - The 4 bytes at offset 80–83 MUST be interpreted as an unsigned 32-bit little-endian integer $N$ representing total facet count.
   - The total file length in bytes MUST strictly equal:
     $$\text{FileSize} = 84 + (50 \times N)$$
   - If the byte size does not match this exact formula, the file MUST be rejected immediately as truncated, malformed, or corrupt.
2. **ASCII STL Ambiguity Guard**:
   - The first 6 bytes of the file MUST NOT match the ASCII string `"solid "`. Any file starting with `"solid "` MUST be rejected.
3. **Finite Float Verification**:
   - For every facet $i \in [0, N-1]$, the 50-byte facet record MUST be parsed into twelve 32-bit single-precision floats (3 normal components $n_x, n_y, n_z$ and 9 vertex coordinates $v1, v2, v3$) and one 16-bit attribute integer.
   - Every float value MUST be checked with `Number.isFinite()` / `math.isfinite()`.
   - If any coordinate contains IEEE 754 `NaN`, `+Infinity`, or `-Infinity`, the file MUST be rejected.
4. **Degenerate Geometry Rejection**:
   - If $N > 0$, the mesh MUST NOT contain solely $(0, 0, 0)$ vertex coordinates.
   - Coordinate vertices MUST fall within the allowable engineering coordinate bounds of $[-100000.0, 100000.0]\text{ mm}$.
   - Vertices exceeding these bounds MUST trigger rejection.

#### Scenario: Valid binary STL adhering to exact formula passes validation
- GIVEN a binary STL file with 1,200 facets, exact size $84 + (50 \times 1200) = 60,084$ bytes, and finite coordinates
- WHEN integrity validation runs
- THEN validation succeeds without error and records `facetCount = 1200`

#### Scenario: Truncated binary STL is rejected
- GIVEN a file claiming 100 facets ($84 + 5000 = 5084$ bytes) but containing only 4,200 bytes on disk
- WHEN integrity validation runs
- THEN validation fails with a size mismatch error and the file is rejected

#### Scenario: Binary STL with NaN coordinates is rejected
- GIVEN a binary STL file matching the byte length formula but containing a `NaN` float in vertex 2 of facet 14
- WHEN coordinate validation evaluates the facets
- THEN validation fails with a non-finite coordinate error and execution aborts

#### Scenario: Degenerate all-zero STL is rejected
- GIVEN a binary STL file with 50 facets where every single vertex float is `0.0`
- WHEN coordinate validation evaluates the facets
- THEN validation fails with a degenerate all-zero geometry error

### Requirement: Magic Header Byte Validation for Native CAD and 3D Files
All native CAD and 3D scene files MUST have their magic header signatures validated prior to storage, execution, or delivery:
1. **AutoCAD DWG (`*.dwg`)**:
   - The first 6 bytes of the file MUST match a valid AutoCAD release signature:
     - `AC1015` (AutoCAD 2000)
     - `AC1018` (AutoCAD 2004)
     - `AC1021` (AutoCAD 2007)
     - `AC1024` (AutoCAD 2010)
     - `AC1027` (AutoCAD 2013)
     - `AC1032` (AutoCAD 2018–2026)
   - Files with missing or non-matching magic bytes MUST be rejected.
2. **FreeCAD FCStd (`*.FCStd`)**:
   - Bytes 0–3 MUST match the standard ZIP Local File Header magic signature: `0x50 0x4B 0x03 0x04` (`PK\x03\x04`).
   - The archive MUST contain a valid internal `Document.xml` entry.
3. **Blender Blend (`*.blend`)**:
   - The first 12 bytes of the file MUST match the regular expression:
     `^BLENDER[-_][vV][0-9]{3}$`
     (e.g., `BLENDER-v400` or `BLENDER_v306`).
   - Files lacking this signature MUST be rejected.

#### Scenario: Valid AutoCAD DWG header passes validation
- GIVEN a DWG file starting with bytes `"AC1032"`
- WHEN magic header validation runs
- THEN the file is verified as a valid AutoCAD DWG release 2018-2026

#### Scenario: Plain text file disguised as DWG is rejected
- GIVEN a text file renamed to `plan.dwg` starting with `"Hello World"`
- WHEN magic header validation runs
- THEN the file is rejected with an invalid DWG signature error

#### Scenario: Valid FreeCAD FCStd archive passes validation
- GIVEN an FCStd file starting with `PK\x03\x04` containing `Document.xml`
- WHEN magic header validation runs
- THEN the file is verified as a valid FreeCAD document

#### Scenario: Valid Blender blend file passes validation
- GIVEN a Blender project file starting with `"BLENDER-v400"`
- WHEN magic header validation runs
- THEN the file is verified as a valid Blender scene

### Requirement: Pre-Delivery Validation Gates Across Pipelines
Integrity validation MUST be enforced at three non-bypassable architectural gates:
1. **Agent Result Gate (`agent/cadgpt_agent/upload.py` / `executor.py`)**:
   - Before uploading a generated mesh or CAD artifact, the agent MUST run local binary STL coordinate validation and magic header checks.
   - If validation fails, the agent MUST NOT upload the corrupt file and MUST report execution failure.
2. **API Mesh Upload Ingestion Gate (`apps/api/src/mesh.ts`)**:
   - During HTTP streaming (`POST /api/agent/jobs/:id/mesh`), the API MUST stream bytes into a `.part` file while verifying the SHA-256 hash and header.
   - Before renaming `.part` to final `.stl`, the API MUST execute the full binary STL validator ($84 + 50 \times N$ size check and finite float coordinate check).
   - If validation fails, the API MUST immediately unlink the `.part` file and respond with HTTP 400.
3. **API File Download / Serve Gate (`apps/api/src/mesh.ts` & file serve endpoints)**:
   - Before streaming mesh or native CAD files to web browsers or download clients, the API MUST verify that the on-disk file passes size and magic header validation.
   - If corruption is detected on disk, the API MUST return HTTP 500 with an integrity failure error instead of streaming corrupt bytes.

#### Scenario: Agent refuses to upload corrupt mesh
- GIVEN an agent job whose CAD worker generated a truncated STL file
- WHEN the agent upload routine inspects the output file
- THEN the agent rejects upload, removes temporary artifacts, and reports a job execution failure

#### Scenario: API upload rejects stream with corrupted floats
- GIVEN an agent uploading an STL file containing `Infinity` values in its facet stream
- WHEN the upload completes and validation runs
- THEN the API rejects the file, deletes the partial upload, and returns HTTP 400

#### Scenario: Serve gate blocks corrupted file on disk
- GIVEN a file on the server filesystem whose header bytes were corrupted after storage
- WHEN a client requests `GET /api/designs/:id/mesh`
- THEN the serve gate catches the corrupted header and returns HTTP 500 without sending corrupt geometry to the browser
